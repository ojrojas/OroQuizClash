# Accessibility Specification (WCAG 2.2 AA)

Applies to both expressions; verified per theme independently (never inferred).

## Contrast (verified pairs in `design-tokens.json` `contrastPairs`)

- Normal text ≥ 4.5:1; large text (≥24px / 18.66px bold) ≥ 3:1; non-text (icons, focus, borders of controls) ≥ 3:1
- Admin light: body 9.90:1, on-primary 8.72:1, success-text 5.02:1, accent-text 4.80:1, focus 4.94:1
- Player dark: body 17.06:1, accent-text 8.31:1, success-text 10.25:1, destructive-text 6.45:1, focus 3.45:1
- Small colored text MUST use `--color-success-text` / `--color-accent-text` / `--color-destructive-text` (T024/T030 audit fixes)

## Focus

- Ring: `0 0 0 2px var(--color-ring)` — 3:1 minimum vs adjacent (4.94:1 light / 3.45:1 dark)
- Visible on all interactive elements; never `outline: none` without replacement
- Skip-link first in DOM (Admin shell + Player app)

## Keyboard

- All functionality reachable; logical order (nav → filters → content → pagination)
- No traps; Modal/Drawer/Select implement trap + return focus; Esc closes overlays
- Patterns: Tabs arrows + roving tabindex; Select arrows/Enter/Esc/Home/End/typeahead; Table sortable `aria-sort`; AnswerOption shortcuts 1–4
- Documented traversal paths: `research.md` Addendum T024

## ARIA & Semantics

- Landmarks: `banner`, `nav`, `main`, `contentinfo`; one `main` per view
- Headings hierarchical (h1 page → h2 sections → h3 cards)
- Decorative icons `aria-hidden="true"`; meaningful `aria-label`; controls expose name + state (`aria-pressed`, `aria-expanded`, `aria-selected`, `aria-sort`, `aria-disabled`)
- Forms: `<label for>`, errors `aria-describedby` + `aria-invalid`, submit errors `role=alert`
- Live regions: Toast `status`/`alert`; game feedback `aria-live=polite`; outcome `assertive` once; Timer `off` → `polite` at critical; Leaderboard `off` (high frequency)

## No Solo-Color (FR-015)

- Timer warning/critical: color + icon + text + live announcement
- Badges/status: icon or text always present
- Correct/incorrect: icon + text, never border color alone

## Touch & Motor

- Targets ≥ 44×44px (AnswerOption 56px@375)
- Spacing between targets ≥ 8px
- No hover-only functionality

## Forced Colors (Windows High Contrast)

- `@media (forced-colors: active)`: 1px solid CanvasText borders on card/btn/input/modal/drawer/badge/timer; focus outline 2px Highlight (implemented in `design-tokens.css`)
- Never convey state by background alone (borders/icons persist in forced colors)

## Reduced Motion

- `prefers-reduced-motion: reduce` → all animation ≤200ms fade or none (see `motion.md`)
- No information loss: timer state, results, focus remain fully perceivable

## Audit Process

- axe-core AA rule set per theme × breakpoint (375/768/1024/1440) at implementation phases (SPEC-017+); design-phase computed ratios archived in `research.md` Addenda T024/T030
- Manual: keyboard pass, screen reader smoke (NVDA/VoiceOver), forced-colors emulation, reduced-motion emulation
